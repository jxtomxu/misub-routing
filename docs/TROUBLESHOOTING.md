# 故障排查

- **节点为空**：分别确认 MiSub 对应客户端格式、订阅未过期、订阅更新成功以及客户端能解析订阅地址。不要把订阅地址或节点日志发到公开 Issue。
- **Mihomo 无法启动**：检查本机覆写是否提供 `LOCAL_SNELL`、`LOCAL_STATIC` 和 MiSub URL；检查代理链是否存在循环；先看日志中的规则文件、ASN 数据库和 DNS 错误。
- **Mihomo 的 Proxy 无流量**：模板故意把 `REJECT` 放在第一项，导入后必须手动选一个实际节点；避免尚未完成配置就意外直连。
- **规则不更新**：先看 GitHub Actions 最近一次成功时间，再看客户端规则资源更新时间。raw 文件可能被缓存；手动刷新并核对一个已知域名的命中。
- **DNS 异常**：先确认自建 Snell 真正可达和 `#LOCAL_SNELL` 引用正确，再检查启动解析服务器、ChinaMax DNS 覆盖、TUN 劫持及客户端额外 DNS 覆写。不要只依据界面上的 DNS 地址判断真实出口。
- **Grok 出口不对**：检查设备本地的 Grok 特例在 AI 规则前，且静态落地的节点链能连通；未配置该特例时默认 Intelligence。
- **BiliBili 地区内容不对**：该组默认 DIRECT。手动切换到对应节点或 Proxy 后检查实际出口；本项目不建立地区组。
- **同步失败**：查看对应 Actions 日志中失败的上游 ID、HTTP 状态、规则数量或测试；GitHub 仍保留上一版 dist。不要通过关闭校验强行发布。
